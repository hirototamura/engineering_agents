# 再現可能な実行を設定する

選んだシナリオの設定ページから始めます。バックエンド、エージェントのモード、観測期間、受入条件を実行前に決め、比較ごとに異なる実行 ID を使います。

## 小さな設定パッチを保存する

ローカル ECLSS を 1 回実行する例として、`local-run.yaml` を作成します。

```yaml
backend:
  kind: mock
simulation:
  steps: 20
agents:
  actor:
    mode: labeled_rule_base
  design:
    mode: labeled_rule_base
iteration:
  enabled: false
```

実行計画を表示し、実行入力を保存します。

```bash
PYTHONPATH=src python -m tools.cli run ssos_eclss_loop \
  --override-file local-run.yaml --run-id local-review-01 \
  --dry-run --json --write-spec /tmp/local-review-01.json
```

`--dry-run` はシミュレーションやモデルサービスへの接続確認を行いません。`--write-spec` はこの場合もファイルを書きます。仕様には上書き設定と実行制御を記録し、マージ済みの全既定値は含めません。リポジトリのリビジョンも残してください。完了した実行には実効設定が保存されます。

計画を確認したら `--dry-run --json` を外して実行します。一時的な変更には `--set simulation.steps=30` を使えます。`--steps 40` のような専用オプションがより優先されます。正確なマージと出力先の規則は[設定リファレンス](../reference/configuration.md)で説明します。

## 完了を確認する

出力の summary でシナリオ、バックエンド、モード、観測期間、保存先を確認します。CLI の既定値を推測せず、保存設定を見てください。正常終了だけでは設計要求を満たしたと判断できません。[結果の確認](inspect-results.md)へ進みます。

設計比較では、要求、初期条件、故障予定、評価バージョンを固定します。ECLSS の連鎖実行は比較条件を凍結し、キューブの条件と乱数種は凍結 SSOT から得ます。引き渡しの手順は[設計の反復](design-iterations.md)を参照してください。

## 比較前に変えるものを宣言する

元の比較手順は、世界の条件とエージェントの選択を分けていました。小さな実験メモでもこの区別を残します。

| 実験の要素 | 宣言例 | 残す理由 |
| --- | --- | --- |
| 世界と初期状態 | 同じバックエンド、初期資源、異常・故障予定 | 世界が違えば別の実験になる |
| 検証 | 同じ要求、観測期間、評価器の版 | 物差しの変更を避ける |
| 試す変数 | designer モード、装置容量、1 つの制御キャンペーン | 差を解釈できるようにする |
| 外部サービス | 解決したモデル・provider・生成設定 | モデル応答は完全再現とは限らない |
| 出力の識別 | ベースラインと候補の別ディレクトリ | 比較の両側を保持する |

モード比較で容量も変え、その差をエージェントの効果と呼ばないでください。設計比較ではファイル名だけでなく、消費した入力と実効設定を確認します。
