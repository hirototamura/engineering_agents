# 実行の問題を調べる

再試行する前に、出力ディレクトリ、実行コマンド、リポジトリのリビジョン、モデルサービスの設定を保存します。再試行には新しい実行 ID を使い、調査対象の証拠を保持してください。

## コマンドや設定が拒否される

チェックアウトのルートから `PYTHONPATH=src python -m tools.cli --help` を使います。インストール済みパッケージと現在のソースが異なる場合があります。Python 3.11 以上が必要です。ECLSS/スクラバーの `--set` は未知のキーを拒否するため、scenario と agents の正確なパスを使います。上書きファイルは設定マッピングであり、外部シナリオ定義ではありません。

ECLSS が想定外に連鎖実行したり LLM を要求したりする場合は[既定値](../scenarios/ssos_eclss_loop/configuration.md)を確認します。小さなローカル実行では backend・actor・design と `--set iteration.enabled=false` を指定します。dry-run は計画確認であり、全実行環境の検証ではありません。

## サービスやバックエンドに接続できない

`PYTHONPATH=src python -m tools.cli doctor` を実行し、接続性と保存計画の正確な URL・モデルを確認します。研究室の vLLM には該当ネットワーク、Ollama には稼働中のサービスと対象モデルが必要です。[LLM 接続](llm.md)を参照してください。

ROS2 ECLSS には SSOS コンテナとマウントが必要ですが、mock と plant_sim には不要です。キューブには既存 SSOT ストアと[追加依存](../scenarios/balancing_cube/configuration.md)が必要です。GPU 検証の欠如は明示的な `not_run` であり、CPU 検証を GPU 比較と呼ぶことはできません。

## 結果が欠ける・判定不能になる

ビューアより先に `summary.json` を確認します。ECLSS の完全な採点には `plant_sim` と生存追跡が必要で、mock はその対象外です。`evaluation_status`、物理ゲート、整合性記録、軸ごとの状態を調べます。キューブは `status: inconclusive` で終了する場合があるため、その理由と依存・同期の記録を確認します。

提案が拒否された場合は、バックエンド非対応、rejected、監督承認待ちなどを区別します。完了表示だけを得るためにゲートを回避せず、対象の[シナリオ](../scenarios/index.md)の結果契約を読み、変更する条件を決めてから再実行します。

## 出力先を使えない

ECLSS/スクラバーは認識した実行ディレクトリを通常は置換します。無関係な内容の削除には `--force` が必要です。単一実行の `--no-recreate` は最初の削除を避けますが、ストリーム追記と summary 上書きが起こります。連鎖では親だけを保持し、メモリを消去して子実行とリプレイを再作成します。再開や証拠保持の保証ではありません。キューブは空でない実行先を拒否します。比較には新規ディレクトリを使います。[出力先の規則](../reference/configuration.md)を参照してください。

## 最初に信頼できる記録から切り分ける

| 症状 | 最初に読むもの | 次の対応 |
| --- | --- | --- |
| 出力ディレクトリがない | CLI エラーと dry-run 計画 | 入力・前提を直してから再試行 |
| ディレクトリはあるが summary が欠損・不正 | 途中ストリームと最後の段階・エラー | 部分実行を保持し、完了と呼ばない |
| 提案はあるが次回が変わらない | 承認理由と消費済み入力 | 適用対応と状態ゲートを確認 |
| mock/ROS2 に完全な点数がない | 評価の適用範囲 | バックエンドに合う証拠を選ぶ |
| キューブが次の提案前に停止 | 基準の結果と同期状態 | 記録された失敗・配送待ちを解決 |
| ビューアと手計算が違う | 行選択、時間窓、単位、分母 | 所有シナリオの解釈に合わせる |

再試行は新しい保存先を使います。失敗と修正後の記録を並べ、変更理由をレビューできるようにします。
