# 内部の保存契約

成果物の意味とシナリオ別の出力は[利用者向け成果物リファレンス](../../users/reference/artifacts.md)が定義します。このページではコード変更に関係する保存部品、回復時の動作、限界を示します。

## パスと再作成

`scenario/jobs/resolve.py` は明示した出力ディレクトリ、または結果ルートと実行 ID から出力先を決め、派生パスを作る前に ID を検査します。公開するルートの優先順位、既定トラック、ID 構文は[出力設定の契約](../../users/reference/configuration.md)で定義します。解決処理の変更はその契約とパストラバーサルの拒否を維持する必要があります。

`EventLog.prepare_run_dir()` は既存の通常実行ディレクトリを作り直します。`remove_run_directory()` はファイルや、実行成果物の目印がない空でないディレクトリを、強制指定なしでは削除しません。これは無関係なディレクトリの削除を防ぎますが、再作成を指定した既存実行は保護しません。キューブは空でない出力先を拒否し、設計実行を不変に保ちます。

## 書き込みと読み込み

`EventLog.append()` はメッセージ、テレメトリ、健全性、EPS テレメトリ、イベント、設計状態、記憶の理由という定義済みストリームだけを受け付けます。各呼び出しは対応する JSONL を追記モードで開きます。`write_summary()` は `summary.json` を置き換えます。複数ファイルのトランザクションや、不変な成果物サービスではありません。

`ArtifactStore.read_json()` はファイル欠落、不正 JSON、オブジェクト以外の値に `{}` を返します。すべての入出力エラーを捕捉するわけではありません。`write_json()` は親ディレクトリを作り、指定 JSON 文書を置き換えます。この寛容な読み込みは欠落を許す場所だけで使います。実行器は要約を別途厳密に検証します。

`SessionStore` はそのインスタンス内のロックでエージェント別 JSONL を書き、読み込みでは不正な行を飛ばします。プロセス間のロックやアクセス制御ではありません。`ClaimsRegistry` は有効・撤回の主張を保存し、語句で検査します。破損入力の読み込み時はメモリ上の主張一覧を空にします。

## 保存機能の保証は同一ではない

| 部品 | 書き込み | 読み込み・失敗 | 呼び出し側の責務 |
| --- | --- | --- | --- |
| `EventLog` | JSONL 1 行の追記と要約の置換 | 不明なストリームを拒否 | 行の意味と出力ライフサイクルを決める |
| `ArtifactStore` | 名前付き JSON の置換 | 欠落・不正・オブジェクト以外は `{}` | 欠落を許せる場所だけで使う |
| `SessionStore` | 個別セッションへインスタンス内ロック付き追記 | 不正な行を飛ばす | 呼び出し側で相互参照を制限する |
| `ClaimsRegistry` | 有効・撤回の主張を保存 | 破損読み込みでメモリ上の一覧を消す | 語句検査を意味の証明にしない |
| 実行器の要約読み込み | 失敗した証拠を修復しない | 欠落・破損・空・非オブジェクトは失敗 | 完了を作り出さず失敗を保持する |

次は主張の契約の例であり、全体共通の文書検証器ではありません。

```python
claims.register(agent_id="designer", candidate_id="run-a:candidate-1", fields={"sizing": 12.0})
claims.register(agent_id="designer", candidate_id="run-a:candidate-2", fields={"sizing": 15.0})
claims.retract_except("run-a:candidate-2")
hits = claims.sweep_text("Adopt run-a:candidate-1.")
```

古い候補の名前空間付き識別子を検出します。末尾だけの名前は複数実行に一致するため使いません。有効な主張とも共有する語句は許容します。近くの撤回マーカーで言及に留保を付けられます。正しさの主要な根拠は保存証拠と選択候補の ID です。

## シナリオ固有の強い保証

機械系の `atomic_json()` は有限値だけの JSON を一時ファイル経由で置き換えます。キューブは入力を固定し、不完全な評価を分離して残し、永続的な連携送信箱を使います。これらの保証が他の成果物にも自動で適用されるわけではありません。設計コードは出典を残し、値の欠落を合格した測定と解釈しないでください。

確認先は `tests/core/test_design_storage.py`、`tests/scenario/test_run_spec.py`、`test_write_effective_configs.py` とキューブの不変性・同期のテストです。保存を変えるときは、ダッシュボードや分析ツールの読み手が厳密か寛容かも確認します。
