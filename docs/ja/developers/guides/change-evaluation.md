# 評価を変更する

変更する主張が、制約の受入判断、最適化、モデルの不変条件、数値的一致、実機の妥当性確認のどれかを明示します。式を変える前に[評価の責務](../evaluation.md)と対象の[シナリオ評価器](../scenarios/index.md)を確認してください。

## 変更を追跡して実装する

1. 正本の要件と使用する保存済み入力を特定します。単位、時系列行の選択、期間、欠落・非有限値、適用範囲を定義します。
2. 実行要約、候補順位、最終回答、連鎖記憶、ダッシュボード、レポートなど、すべての利用箇所を確認します。ビューアに別の採点を加えず、正本となる計算を 1 つに保ちます。
3. シナリオの評価器を変更します。SSOS は実行後の設計より前に確定し、一度だけ実行の測定結果を書きます。キューブの制約検査・数値的一致と最適化目的は分離したままにします。
4. 意味や重みが変わる場合は、必要なスキーマの版と比較可能性の説明を更新します。権限の根拠が変われば新しい要件・契約の版を記録します。新しい式で過去の得点を黙って再解釈しません。
5. 利用者向けの結果の説明と、開発者向けの契約を両言語で更新します。提案と実行済み候補を区別します。

## 変更の影響範囲

| 変更する動作 | 正本計算の確認 | 利用側の確認 |
| --- | --- | --- |
| 時間集計 | 操作前後の行と実際の期間 | 軌跡要約と表示する最終状態 |
| ハード制約 | 欠落・非有限・境界の等号 | 候補の適格性と採用の区別 |
| 目的・重み | 版と比較可能な入力集合 | 順位、最良案、記憶、表示用投影 |
| 物理監査 | 必須テレメトリと残差許容値 | 不完全・失敗・未実行の区別 |
| 数値的一致 | 試行キー、区間、許容差 | GPU 未実行を検証済みにしない |
| 適用範囲 | 生の評価器と最終化をまとめて確認 | 保存状態と空値・真偽値の指標 |

最終化が生の非適用結果を無効にする場合があるため、適用範囲は独立した回帰対象です。SSOS の[評価契約](../scenarios/ssos_eclss_loop/evaluation.md)は現在の制限を記述しています。純粋な評価器だけのテストでは検出できません。

## 必要な確認

各ゲートの直前・境界・直後、欠落値、数値欄の真偽値、非有限値、不完全な軌跡、試行の重複、未対応の契約を必要に応じてテストします。無効な候補や同点の順位も確認します。高い最適化スコアで、制約違反や証拠欠落を回避できてはいけません。

SSOS では操作前後の代表行、物理ゲートの不完全状態、完全性による無効化、候補の適格性、連鎖の最終回答、操作エージェントの有無による満点の差を確認します。キューブでは固定試行行列、必要期間、固定時間刻みの CPU/GPU 比較、ゲート付近の不確定、GPU 不在、部分実行の証拠保持、同期失敗を確認します。

対象のテスト後に[通常の確認コマンド](../contributing.md)を実行します。文書変更に伴って過去の実験を再採点しません。別途認められた研究比較では、監査できるよう両方の評価器の版、入力、条件を保持してください。
