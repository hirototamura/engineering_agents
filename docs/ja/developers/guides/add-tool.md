# エージェントのツールを追加する

繰り返し現れるエンジニアリング上の問いに、決定論的で確認可能な操作が必要なときにツールを追加します。証拠を読む、派生量を計算する、設計を提案する、候補を実行する、のどれかを先に決めます。この区別が副作用、来歴、結果から主張できる範囲を決めます。

## 担当ツール群を拡張する

SSOS は [design_tools.py](https://github.com/hirototamura/engineering_agents/blob/main/src/scenario/ssos_eclss_loop/design_tools.py) を変更します。

1. 入力の単位、範囲、欠落データの扱い、コンパクトな JSON 直列化可能な結果を定義し、処理を実装します。
2. ハンドラと `ToolSpec` を登録し、`catalog()`、`tool_names()`、`call()` を一致させます。設計器が正しく使えるだけの引数の意味を示します。
3. ツール利用が証拠の収集義務を満たす場合は、そのラベルを明示的に追加します。成功した設計器の呼び出しだけを実施済みと数えます。レポート作成は `record_evidence=False` を使え、エージェントが比較を行ったという記録を作ってはいけません。
4. 必要な場合だけ `scenario/agents/ssos_tool_use_design.py` のトレースとプロンプトを接続します。上限、修復処理、来歴を維持します。

キューブのツールと専門家間の受け渡しは、専用アダプタとワークフローが担当します。`tools/` の分析スクリプトは自動でエージェントに公開されません。具体的な複数シナリオの要件がない段階で、プロジェクト全体のレジストリを導入しないでください。

## 公開前に操作を定義する

| 種類 | 成功結果で区別するもの | 主な拒否入力 | 必要なテスト |
| --- | --- | --- | --- |
| 証拠の読み出し | 存在、欠落、破損、意図した省略 | 不明な成果物・出典 | 欠落を欠落のまま扱う |
| 派生計算 | 入力測定、単位、方法、計算結果 | 非有限・不整合な量 | 独立した期待値の計算 |
| 提案の構築 | 推奨項目と設置済み項目 | 未対応変数 | 状態と証拠を変更しない |
| 候補実行 | 適用入力、実行 ID、測定結果 | 不正設計・上限到達 | 失敗時も証拠を確認可能 |
| 比較 | 比較条件と決定論的な順位 | 要件変更・結果欠落 | 高得点の無効候補が勝たない |

現行の具体例は SSOS の[ツールカタログと固定手順](../scenarios/ssos_eclss_loop/implementation.md#design-toolkit)にあります。9 操作と Python が呼ぶ順序を示します。カタログへの登録だけで、LLM がツールを自律的に選択するわけではありません。

## 主張の範囲を守る

サイジングはシミュレーションではなく、シミュレーションは検証要件を改訂しません。図を作るツールは画像パスに加えて有用な数値の説明を返します。候補実行は内部の設計を無効にし、出力を分離し、適用設定を保存して通常実行と同じ評価器を使います。

`tests/scenario/test_ssos_design_tools.py` または対象シナリオで、正常入力、不明な名前、不正引数、処理失敗、非有限・欠落データ、決定論的な結果を確認します。変更を伴うツールは、拒否や中断時の許可判断と証拠保持も確認します。失敗を実施済みと数えず、レポートの後処理をエージェントの実績にしないことを確認してください。責務の境界が変わる場合は[ツールと記憶](../tools-memory.md)も更新します。
