# 開発課題

複数のエンジニアリング分野にわたって基盤を改善する変更の範囲を整理します。現行動作は[アーキテクチャ](../architecture.md)、[実行ライフサイクル](../runtime.md)、[内部の実行契約](../reference/execution.md)を参照してください。開発目標は提供済み機能の説明ではありません。

## 外部シナリオの責務

分野をまたぐ主要な目標は、各事例が独自の世界、ツール、要件、評価、証拠を持ったまま、このリポジトリの外で開発できるようにすることです。現行の設定検出、固定レジストリ、CLI の分岐、出力トラック、SSOS 専用の反復は、まだその境界を提供しません。

[外部シナリオ化](external-scenarios.md)では責務の境界、独立してレビューできる開発作業、受入条件を定めます。外部 API、マニフェスト、プラグインの実装方式はまだ定義しません。それらの決定には実装提案と、同梱の 3 シナリオに対する回帰証拠が必要です。

## 文書を動作とともに保守する

[文書の保守](documentation.md)では読者別の担当、現行資料と履歴資料、両言語の更新、確認方法を説明します。文書変更は実在する機能を使いやすく、変更しやすくするために行います。あるシナリオのバックエンド、得点、提案ループが他のすべてでも動くように記述しないでください。

その他の作業は[貢献手順](../contributing.md)に従って具体的に提案します。現在の失敗と、それを解決する最小限の境界を示してください。動作、失敗時の処理、証拠、文書をまとめてレビューできることを完了条件にします。
