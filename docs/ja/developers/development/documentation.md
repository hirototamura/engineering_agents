# ドキュメントを保守する

ドキュメントも変更の契約に含まれます。読者が研究ノートを再構成しなくても、既存機能の設定と結果判断、または変更対象の実装境界へ進めるようにします。

## 読者と目的を決める

`users/` は既存の設計・検証を設定、実行、解釈するエンジニア向けです。`developers/` はコード、シナリオ、ツール、バックエンド、評価、実行基盤を変える開発者向けです。各ページは、最初の作業を完了するチュートリアル、特定の変更を進めるガイド、境界を説明する概念、厳密な動作を定める参照のいずれかを目的にします。

作業別の入口とガイド・参照の分離は、[OpenAI のクイックスタート](https://developers.openai.com/api/docs/quickstart)と [Claude のドキュメント](https://platform.claude.com/docs/ja/home)の構成を参考にしています。本プロジェクト独自の用語、内容、ナビゲーションを使います。

シナリオ固有の内容は各読者区分のシナリオ配下に置きます。スクラバー、SSOS、キューブを対等に扱ってください。公開 CLI、設定、成果物の定義は利用者向け参照に正本を置き、開発者向け文書は内部契約を説明してそこへリンクします。

## 現在の証拠から書く

このチェックアウトのソースとテストを読みます。実装済み、制限、計画、日付付き測定を区別します。利用者の手順には前提、入力、コマンド、期待する証拠、完了の判断を含めます。開発者のガイドには担当モジュール、契約、失敗動作、拡張点、回帰確認を示します。

英語と日本語はページ構造と主張を揃えます。ソースのみの研究資料には実際の言語を表示し、空の翻訳ページを作りません。過去の計画、仕様、レポートは `_archive/` に置き、通常の公開と検索から除きます。現在も有用な知識はソースやテストの根拠を付けて保守対象のページへ抽出します。実験の元の測定値と条件は維持してください。

## 読者の導線を確認する

ソースの[文書規則](https://github.com/hirototamura/engineering_agents/blob/main/docs/AGENTS.md)と[貢献ガイド](https://github.com/hirototamura/engineering_agents/blob/main/AGENTS.md)に従います。両言語の対応パス、ナビゲーション、相対リンク、画像、アンカー、出典、利用者・開発者の導線を確認します。`python -m mkdocs build --strict`、続けて `python scripts/check_docs.py` を実行します。検査は読者区分・言語の対応、生成したリンクとアンカー、読者の導線、言語切り替え、内部規則と履歴資料の公開・検索からの除外を確認します。CLI のヘルプとドライランで記載オプションを確認し、実験は再生成しません。コード変更で変わった動作の主張には関連の回帰テストを実行します。

古い公開ページは削除します。移転用のページ、旧見出しの付録、互換アンカー、リダイレクトを残しません。文書整理のために記録済み実験を再生成・再採点しないでください。
