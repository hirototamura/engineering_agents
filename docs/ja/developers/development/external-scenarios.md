# 外部シナリオ化の開発

**未実装の開発目標です。** 現在は 3 つのシナリオを同梱しています。一覧はローカルの `scenario.yaml` を検出しますが、実行は固定レジストリを結合し、実行器と CLI は名前で分岐します。既定の出力トラックは 2 つで、連鎖反復は SSOS 専用です。任意の外部パッケージを登録できる公開インターフェースはありません。

目標は、独立して保守する事例が分野を担当し、基盤が実行と証拠の仕組みを供給することです。このページは責務の境界、開発作業、受入条件だけを定めます。将来の API、プラグインのスキーマ、実装方式は定義しません。

## 責務の境界

基盤は検出・受付、汎用ジョブのライフサイクル、実行状態、出力の分離、進捗、共有の証拠保存を担当するべきです。ECLSS のテレメトリ、キューブの試行行列、単一の提案形式を前提にせず、対応する能力を示します。

シナリオはミッションと要件の権限、設定検査、世界・モデル構築、設計と実行中の操作、エージェントとツールの構成、評価、成果物の意味を担当します。バックエンドは単位、時計と状態遷移、数値挙動、モデルの証拠を持ちます。連携は正本・来歴の変換と再送を持ちます。ビューアは宣言された証拠を読み、隠れた評価器にならないようにします。

## 開発作業と受入条件

1. **結合箇所を把握する。** ディレクトリ検出、レジストリ、CLI・実行器の分岐、共有部からのシナリオ参照、既定出力トラック、リソース、反復を追跡します。シナリオ固有の各仮定に担当と回帰確認、または明示した不足があることを受入条件にします。
2. **検出と実行受付を一致させる。** 利用可能と実行可能の名前を一致させ、重複、依存欠落、不正定義を明確に失敗させます。外部のテスト用シナリオを、分野のために基盤ソースを編集せず検出でき、安全に拒否できることを確認します。
3. **ライフサイクルと分野操作を分離する。** シナリオ別の振り分け知識を担当する境界へ移します。同梱の 3 事例の対応モードと失敗動作を保持し、未対応操作は実行前に拒否することを確認します。
4. **設定・入力・証拠を分ける。** シナリオの検査、解決済み入力の来歴、提案適用、出力の不変・再作成方針、正本評価を保持します。外部テスト事例が他の実行を上書きできず、証拠欠落を成功にできないことを確認します。
5. **リソースと追加依存を配布可能にする。** YAML・データの梱包とバックエンド・プロバイダの事前確認を整えます。リポジトリ内のソース相対パスに頼らず、インストール済み配布物でテストでき、検出時に利用不能な追加計算系を読み込まないことを確認します。
6. **分野非依存性を確認する。** 契約テストと異なる分野データを持つ最小の外部テスト事例を追加します。同梱シナリオの型を読み込まずに一覧、検査、実行、証拠閲覧、失敗回復が動き、既存の回帰テストも通ることを確認します。
7. **対応境界を公開する。** 動作を実装してから利用者・開発者向け文書を作ります。現行の対応範囲、限界、移行作業、拡張テストを両言語で明示することを受入条件にします。

この目標に、得点の意味、要件、過去の実験結果の変更を混ぜません。それぞれに別の証拠と権限が必要です。
